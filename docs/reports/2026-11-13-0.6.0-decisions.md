## Moved to 0.7.0

- P-transaction (#166): one-box cost +11.6 us per transaction pair against a 30 us budget.
- The SQL listener's per-statement performance path.
- The masking double-pass (cosmetic: BootUI masks quoted text once, `FrameworkWarningsByRoute.java:240-244`); the nonce
  design got a council NO-GO.
- BootUI's SQL Trace panel being unavailable until a DataSource is wrapped (#185 gap row).

## Defaults taken in the last lanes (reversible)

- #184: the `connection` event's `statements` is always -1 (unknown), so no SQL statement pays for a count; only
  BootUI's `ConnectionReacquisition` (a stub here) reads it. c33ad6c3 (pool listeners kept installed) was reverted: it
  did not close the class-level listener race, which release already has for the Engine, Mapper and transactions
  listeners; one follow-up lane covers all of them.
- #185: SQL is recorded where an engine was registered or a statement was routed (write-once); before that a
  SQL-reading check is UNAVAILABLE (fails closed). The SQL Trace panel keeps release's availability (gap row). Known
  limit: after a failed SQLAlchemy listener attach with an engine registered, a SQL check still reads recorded.
