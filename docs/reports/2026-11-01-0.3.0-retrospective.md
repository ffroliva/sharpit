## Worked

- **Probes before rules.** Four design questions were settled by a ten-line experiment instead of a debate: contextvar
  propagation through a long-lived TestClient portal, anyio and pytest-asyncio runners, and a long-lived async runner
  (stale without a wrapper, correct with one). One probe turned a reviewer's claim into a design change.
- **Council rounds on the spec, then the plan.** Three spec rounds and one plan round (Claude, Codex gpt-6-luna, agy
  gemini-3.8-flash-high) raised 9, 7, 6 and then 0 High findings on the spec; nearly all were real (quiet-green paths,
  xdist merge, masking under `FULL`, aiosqlite double counting). Stopping spec-only rounds after round 3 and moving the
  remaining risk into named plan tests was the right call: the reviews kept finding issues in text the last round added.
- **BootUI as the reference.** A dedicated audit of the draft against BootUI's code corrected eight points (confirmed-
  empty evidence, existing per-vulnerability dismissal, the N+1 key, batch counting) before anything was built.
- **Lanes by files, reviewed before merge.** Nine lanes, each reviewed (spec compliance, then quality) and each review
  produced a fix round with a finding → test → red table. Every lane merged cleanly except one spec-doc conflict.
- **Comparing against the base, not a control.** An overhead failure blamed on "machine load" was measured lane vs
  base with `scripts.dev.overhead_check`, alternating: the lane was 6-9 µs slower (a real cost from building a frozen
  dataclass per statement and routing twice), fixed, then within noise.
- **A real outside proof.** gflow-cli's 5,662 tests under `--sharpit` found 6 N+1s, 0 unattributed statements, and one
  filter gap (`schema_migrations`) that became a product fix.

## Didn't work, and the mechanism now in place

| What | Root cause | Mechanism |
|---|---|---|
| Three CI jobs failed on the first PR run after a green local gate (`lowest`, `no-sqlalchemy`, `coverage`) | the local gate runs one environment; CI runs four | rule in `skills/check/SKILL.md`: run the special jobs locally before a dependency/plugin PR; regression test `test_ini_types_exist_in_the_oldest_supported_pytest` |
| The plugin's ini option types crashed pytest 8.2 (every user on an older pytest would have hit it) | an API used without checking the floor | the regression test above; the `lowest` job |
| Order-dependent failures (log-tail, masking corpus) | in-process pytester runs left logging reconfigured | autouse guard in `tests/conftest.py` fails the leaking test itself; rule in `docs/development/workflow.md` |
| A flaky lifespan test on a fast runner | the test assumed a 5 ms poller had already run | the test waits on a counter; rule in `workflow.md` |
| A spurious `test_osv` teardown error | `npm run build` ran in the worktree while its pytest ran | rule in `skills/check/SKILL.md` |
| Fix rounds reported "test added, passed" without a red | agents wrote the fix first | red proof against the pre-fix tree, rule in `workflow.md`; one test failed it and was strengthened |
| Two fix rounds introduced new defects (snapshot reuse key, advisor order) | fixes reviewed only as part of the next full review | re-review the fix commits on their own, rule in `workflow.md` |
| SonarCloud gate: new-code coverage 59% | pytester subprocess runs were not measured | `[tool.coverage.run] patch = ["subprocess"]` in `pyproject.toml` |
| `main` red after the merge (Sonar ratchet 122 < 123) | the baseline is lowered by hand | rule in `skills/release/SKILL.md` gate 2 |
| Codex and claude-flavio both hit 5-hour limits mid-lane | two heavy lanes on one account at once | WIP-commit rule in every brief held: nothing was lost; lanes resumed on another account from the WIP commit |

## Rulings (coordinator, owner away)

- Spec approval replaced by builder check + `llm-council --tier high` (owner's instruction, spec §15).
- `unknown` fails the build by default; a run with no SQL can pass unless sharpit saw signs of SQL it cannot see.
- Untagged statements stay unattributed (no fallback to the current test window): blaming the running test for a
  thread's work is worse than reporting it unattributed.
- `SqlEvent` is a `NamedTuple` (per-statement cost); report masker ignores `FULL`; fingerprints hash the masked target.
- Migration tables (`alembic_version`, `schema_migrations`, `flyway_schema_history`, `django_migrations`,
  `knex_migrations`) are filtered in the test session only; the console stays unfiltered, as in BootUI.
- Merges: the owner's goal authorised merging the PR to `main` when green and reviewed; `docs/development/workflow.md`
  still says agents never merge. The owner decides whether that line changes.
