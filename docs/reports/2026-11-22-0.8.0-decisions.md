# sharpit 0.8.0: decisions record

0.8.0 targets BootUI 2.5.0 (pinned tag `v2.5.0`). This file records the maintainer's rulings and the defaults taken
during the 0.8.0 lanes (2026-11-20 to 2026-11-22), so they outlive the working notes. A default taken is reversible: its
deviation row in `docs/reference/matrix-updates/` says so.

## Moved to the next release

Each stays a recorded gap with its blocker in PLAN.md ("Recorded, not in this release"):

- 2.5.0 live goldens and the 0.7.0 live goldens: they need BootUI built into the reference application with its
  databases.
- Same-route baselines and authorization evidence: they need the request-journal route and the `authorization`
  journal source, which are not ported.
- Instance discovery and `init` (BootUI #1687): the action conflicts with the rule that a console installed in a host
  application opens no socket.
- 0.7.0 lanes A2 and B2 (transaction boundaries and journal source): over the 30 µs listener budget; they need a
  constant-time design first.
- 0.7.0 lanes B3 to B7 (further journal sources, missing and partial routes) and D1 to D4 (SQL capture hot path).
- The `SHARPIT_EMAIL_MASK_CONTENT` fail-safe fallback (D6 remainder).
- `paged-without-order`: it rests on SQL row-limit and shape analysis that is not ported.
- The ten applicable 2.5.0 rules listed as `missing` in the PARITY 0.8.0 section (`RAPI-MAP-012`, `RAPI-MAP-013`,
  `RAPI-VER-008`, `RAPI-VALID-007`, `RAPI-PAGE-004`, `DB-SCHEMA-011`, `DB-PG-006`, `DB-POOL-005`, `DB-SERVER-008`,
  `DB-MYSQL-004`).
- Consolidating trace masking and journal masking onto the matrix masking path.
- The command-line option naming (`--api` and `--url`) in the live-verification skill document.
- The Windows test `test_session_stream_sends_sessions_then_dashboard`, which fails intermittently on CI.
- The Flask console (`sharpit.install` for Flask) and Flask request correlation.

## Defaults taken (reversible)

- A8: the request ID header is named `X-Sharpit-Request-Id`; trusted-proxy peers and forwarded headers do not grant
  trust, the raw-peer guard is the only trust test; the header is emitted only while the HTTP exchange buffer is
  available, so every emitted id resolves to a recorded exchange.
- A4a: validation errors store the Pydantic `type` and `loc` and the error count, never the rendered message; unknown
  custom error types read `Invalid` below `FULL`; locations that cannot be resolved against a body model keep the
  location prefix and redact every following segment.
- A3: `route-latency-outliers` groups masked SQL shapes by their case-insensitive normalized text, since only masked
  shapes are retained.
- A1, A6: rules retired in BootUI 2.5.0 stay registered and return `SKIPPED`; rules specific to Java, Spring,
  Hibernate or Oracle are `n-a`.
- A5: malicious-package guidance and Maven-specific vulnerability reach are not ported.
- A7: request-profile stepping moves between profileable entries in the loaded feed; the drawer-specific controls have
  no counterpart in the inline Activity profile.
- #207: `--sharpit-app` reports an application whose routes cannot be read as `UNKNOWN`; a suite that named such an
  object and passed before ends as `unknown` unless `--sharpit-allow-unknown` is passed.
- F1, F2: Flask is read through `sys.modules` and never imported by the plugin; the lowest supported Flask version is
  named in the lane plan.
