## Moved to the next release

The release is accepted with these gaps; each has a follow-up issue on the 0.10.0 milestone.

- **Flask console, lanes F1–F6** (#260). F0, the console contract, is merged in `engine/console` and not wired. The
  response corpus that guards the handler move (F1a) failed CI three times and is reverted; its replacement compares
  base and head in the same CI job. The definition-of-done items that need Track F (the F1 corpus, live-verify on a
  Flask sample) move with it.
- **Journal sources and insight kinds, lanes J0–J5** (#299). J0 must first fit the transaction pair inside the 30 µs
  budget that blocked the same lanes in 0.7.0.
- **Route parity, lanes R1–R3** (#300). They were ordered after the console handler extraction.
- **`paged-without-order`, lane M3** (#301). It needs SQL row-limit and shape analysis that holds under masking.
- **Masked exception message in swallowed-exception findings, lane X1** (#253 item 1). It needs a masking corpus diff
  and a council review.
- **Trace and journal masking on the matrix path, lane X3** (#302). It needs a byte-identical masking corpus diff.
- **H6, CodeQL on pull requests into `release/**`.** A workflow change into `main` that awaits the maintainer's go;
  the 0.9.0 release pull request runs CodeQL and the code-scan ratchet before it merges.

## Defaults taken (reversible)

- DB-PG-006 scans `current_schema()` only, like the other PostgreSQL vendor rules; BootUI scans every non-system schema.
- DB-POOL-005 reads SQLAlchemy's `QueuePool` timeout (`None` disables the timeout, `0` fails at once) in place of the
  HikariCP and Agroal acquisition timeouts.
- SQL Trace is available once a SQLAlchemy source is wrapped or an engine is registered, in place of BootUI's
  `hasWrappedDataSource()` check after a Spring `DataSource` bean is wrapped.
- The connection journal derives a connection's statement count at check-in from the SQL Trace rows instead of
  counting per statement, so executed statements pay nothing; the count is -1 when those rows cannot answer.
- Each of these has its row in `docs/reference/matrix-updates/` and the 0.9.0 section of `docs/reference/PARITY.md`.
