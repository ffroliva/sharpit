# sharpit 0.5.0: SQL output architecture decisions (2026-11-05 to 2026-11-08)

The SQL output architecture overhaul replaced the single global `mysql` boolean with per-event dialect resolution,
server-backed lexing rules for supported database families (MySQL family, PostgreSQL, SQLite), structured driver error
regions, and fail-closed handling for unsupported databases. Work was executed across coordinated task branches and
validated against differential masking gates and containerised server oracles.

This document records the architectural decisions, owner rulings with dates, and gate verification numbers on build
`f3be0ead`.

## Decisions and owner rulings

### 1. Driver exception classification and region isolation (2026-11-07 12:42 UTC, 13:39 UTC)

- **Ruling (12:42 UTC):** Alternative B was adopted over regex-based rewriting. Test inputs supply real database
  driver exception instances (such as psycopg `InvalidTextRepresentation`).
- **Ruling D1 (12:42 UTC):** A classified database driver exception shows only its driver class `(module.Class)`,
  one structured code, the masked `[SQL: ...]` block, and `[parameters: ******]` when parameters were bound. Driver
  free-text messages are never displayed, preventing unquoted values echoed by database drivers from leaking into
  logs or traces.
- **Rulings R1 & R2 (13:39 UTC):** Fixture rows assert dialect and class-only output when neither code nor statement
  exists. Unclassified exceptions captured from log records fall back to formatted message rendering via `mask_text`,
  failing closed.

### 2. Test execution parallelism (2026-11-07 14:25 UTC)

- **Ruling:** `AGENTS.md` mandates `-n auto` (pytest-xdist) by default for all test runs across agents, locally and
  in delegated briefs. Lower concurrency or `-n 0` is reserved for system-load limits or isolated budget tests.

### 3. Parameter placeholder preservation (2026-11-07 15:57 UTC)

- **Ruling:** When bound values exist on an executed query or driver error, the masked constant block
  `[parameters: ******]` is retained in rendered output. Readers see that parameters were bound without exposing any
  parameter value or structure.

### 4. Structured driver error codes (2026-11-07 18:17 UTC)

- **Ruling:** Structured error codes are extracted directly through descriptors without invoking arbitrary property
  methods or Python getters: integer `args[0]`, exact 5-character `sqlstate` or `pgcode`, or `sqlite_errorname`
  (such as `SQLITE_ERROR`). If no structured code is present, only the driver class is shown.

### 5. Unsupported database statements and parameter capture (2026-11-07 18:59 UTC, Item 7)

- **Ruling (A + A2 + W):** A statement whose database family cannot be proven (`UNSUPPORTED`) displays
  `[statement hidden: unsupported database]` across all exposure levels, including `FULL`. Parameter capture
  (`capture_parameters=True`) does not reveal unsupported statements.
- Installing with capture enabled adds an activation-status warning that inline literals and error text show unmasked
  for supported databases.
- `statement_shape` wraps its lexer scan in a guard so unparseable or unsupported text degrades safely and never
  raises into the host application.

### 6. Unsupported driver error rendering (2026-11-07 19:31 UTC, Item 8)

- **Ruling:** An error from an unsupported database provider renders as a classified exception: leading
  `(module.Class)`, structured code, the statement marker in place of the `[SQL: ...]` block, and
  `[parameters: ******]` when parameters were bound. Driver free text is omitted entirely.

### 7. Dialect routing and verbless statement surfaces (2026-11-07 19:53 UTC, 2026-11-08 04:47 UTC, Item 5)

- **Ruling (19:53 UTC):** Removing the heuristic verb-led route was conditioned on measurements confirming zero
  increase in secrets shown on any prefix or surface compared to checkpoint CP6.
- **Ruling (04:47 UTC):** Verification showed that verbless text routed to statement surfaces behaves consistently with
  verb-led queries. Stated limit accepted: "text an application writes as a statement is read as SQL". Free text arriving
  on log and exception surfaces is handled by text-masking passes.

### 8. CP9 red classifications and test runner layout (2026-11-08 04:47 UTC, Ruling 2)

- **Ruling:** CP9 red test failures were triaged by root cause:
  - 26 verb-branch rows were re-pointed to log and exception surfaces where non-SQL text occurs.
  - 4 text-path driver rows with unquoted values were accepted as stated limits and marked `xfail(strict=True)`.
  - Stale tests lacking application proof were supplied with verified fixtures.
  - `test_gates_bite.py` was moved to a dedicated masking-gates CI job to respect execution time bounds without
    raising shard ceilings.

### 9. Facade boundary and secret pattern tokens (2026-11-08 04:47 UTC, Rulings 3 & 4)

- **Ruling:** Task 30 (deleting forwarder modules) was dropped from 0.5.0; the existing import boundary test already
  enforces access through `sharpit.engine.sqltext`.
- `_MYSQL_NAMED` driver detection was confirmed as hide-only on dialect conflict.
- `pass` and `pw` were added to secret keyword patterns as whole name segments (matching `user_pw` or `DB_PASS` while
  leaving `passenger` and `compass` unmasked); `pwd` and `passwd` remain substring matches.

### 10. Live fuzzing tokens and deferred session pairs (2026-11-08 08:40 UTC)

- **Ruling:** On the MySQL family, `"..."` is a string value unless the session has `ANSI_QUOTES`. Before this
  ruling, the live fuzz skipped every `"` run, and its generator almost never placed a marker inside one: 7 of 35,149
  MySQL strings did. A `"SECRET"` token was added to the generator, so every run now exercises double-quoted values.
  The MySQL-family control rose from 87 to 98 hits to 157 to 166 hits, and the build stayed at 0.
- Live fuzzing against MySQL's `ANSI_QUOTES` session mode was deferred past 0.5.0 and recorded as a documented gap.
- The fuzz harness had two defects, both fixed before these numbers:
  - On PostgreSQL, autocommit was set on SQLAlchemy's pool proxy rather than the driver connection, so after the
    first refused string every later one failed and the run parsed nothing.
  - On MariaDB, routine bodies were read from `routine_definition`, so names it echoed were counted as values.
    Bodies are now read by `CALL`.

### 11. The residue at 200,000 rows (Task 33, 2026-11-08)

At 60,000 rows A2 showed no residue. At 200,000 rows it showed 11 secrets back at seed 11 and 2 at seed 12, and A7
showed 2 newly shown. The owner allowed one rule, then a fail-closed fallback, then approved a second rule:

- **Rule 1:** a name is released only from a hit that is exactly the name, its `=` and its literal. This closed six
  hits in malformed `[SQL: ...]` text, where a hidden run reached past the literal or reached the name from before it.
  Cost: 39 and 28 plain names in that malformed text are now hidden. No secret is newly shown.
- **Fail closed on malformed text** (approved as the fallback): not needed. The lexer read every SQL row cleanly, and
  the remaining row has no SQL block.
- **Rule 2** (owner, 09:30 UTC): in free text, a dotted name ending in a sensitive header (`<token>.set-cookie:`,
  `do.Cookie`) hides its prefix as well as its value.
- **A7 attribution** (owner, 2026-11-08): all 4,364 outputs that differ from `fa2d51e` are attributed to four named
  rules:
  - a token glued to a mask is hidden whole: 4,354;
  - the dotted secret header: 2;
  - the dotted prefix hidden: 4;
  - the header name shown: 4. The owner approved this: a header name is a label, not a secret.

  No output newly shows a secret.
