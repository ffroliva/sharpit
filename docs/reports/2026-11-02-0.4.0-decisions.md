# sharpit 0.4.0: decisions from the coordinated run (2026-11-01 to 2026-11-02)

The 0.4.0 lanes were built by several agents in parallel and merged through `scripts/dev/lane_gate.py`. Each lane's
evidence (handoff, findings, field map, checklist, review) lived under `.superpowers/sdd/0.4.0/` on the lane branches
and is not tracked on `main`. This file keeps the decisions worth knowing later. The evidence itself stays reachable in
the history of the `release/0.4.0` merge: `git log --all -- .superpowers/sdd/0.4.0/lanes/<lane>/` and
`git show <sha>:<path>`.

Companion documents: the narrative retrospective `2026-11-02-0.4.0-overnight-retrospective.md`, the G1G2 red audit
`2026-11-02-g1g2-red-audit.md`, the spec's deviation log (`docs/superpowers/specs/2026-11-01-sharpit-0.4.0-design.md`
§11) and `docs/reference/PARITY.md`.

## Test evidence: what counts as a red

1. **A red is an assertion raised under `tests/`.** An `ImportError`, `AttributeError`, `TypeError`, a crash in a
   fixture, or an assert in `src/` proves nothing. `lane_gate.is_red`/`red_verdicts` and `scripts/dev/red_check.py`
   share this one rule; an assertion with no identifiable frame fails closed.
2. **A red is replayed at its own SHA**, in a detached worktree with `PYTHONPATH=<tree>/src`. A run on the working
   tree, or through the editable install, imports the current code and proves nothing (two lanes were caught this
   way).
3. **A crash or pass is never accepted by ruling.** Eleven G1G2 tests were merged under such a ruling overnight; the
   owner rejected that, and the audit mutation-proved every one (five more gaps found and covered).
4. **A test that passes at its red SHA because the behaviour already existed** is mutation-proven at head (break the
   guarded line, see the assertion) and moved to a `Historical SHA` table with the proof. Never relabelled.
5. **Timing (budget) reds** pass under light load, so they are mutation-proven with a busy-wait in the measured hook.
6. **A parametrised red is recorded by its base id.** A `|` in an id splits the findings table.

## Overhead budgets under load

- A budget is never raised, deselected or marked slow to pass (AGENTS.md rule 5).
- On a saturated machine budget tests fail even at the release base. A lane is accepted on budget-only failures only
  with evidence: paired, interleaved isolation runs lane vs base, and, when the lane fails more often than the base,
  proof that its code is not on the measured path (a `sys.setprofile` count of lane-module calls during the test body,
  and for `sys.monitoring` users, the registered tool ids). A lane with no `src/` diff cannot move a budget.
- Budget tests are identified by rule (name contains `budget`, module calls `check_budget(`), not by a hard-coded list.
- Follow-up: the N+1 lazy-load budget test runs 5 rounds and flakes on busy machines; a 21-round run measured
  +25.3 µs per lazy load against 35 µs. Raise the rounds, never the budget.

## The merge gate

- The gate refuses a lane whose evidence does not name the reviewed head. An evidence-only change after review
  (`.superpowers/` only, verified by `git diff`) is re-stamped by the coordinator with a note; any code change gets a
  fresh review.
- A change to the gate itself is gated by the branch's own copy after the release copy refuses only the defect being
  fixed (F overnight; the red audit's AST budget detection). Cost if wrong: a gate bug lets its own fix through,
  mitigated by independent reviews.
- Park rule: two failed reviews park a lane. Exceptions were made four times (F, A-data, A-traces,
  T-swallowed-exceptions) for a single narrow finding, each logged.

## Product decisions

- SQL error cleanup applies only to recognised SQL error text; Python tracebacks and plain exception messages keep
  their lines (masking still applies).
- The swallowed-exception predicate follows a nested function only when the handler calls or references it; an
  unused nested function is skipped. When unsure it reports nothing: a missed finding beats failing a correct test.
- sharpit never changes how a user's query executes: the removed `do_orm_execute` hook rewrote execution options and
  broke `yield_per` with `unique()` on SQLAlchemy 2.0.38.
