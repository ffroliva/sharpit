# sharpit 0.5.0: decisions from the coordinated run (2026-11-03 to 2026-11-04)

The 0.5.0 lanes were built by several agents in parallel and merged into the local branch `release/0.5.0` through
`scripts/dev/lane_gate.py`. Each lane's evidence (handoff, findings, field map, checklist, review, gate logs) lived under
`.superpowers/sdd/0.5.0/lanes/<lane>/` and is not tracked on `main`. This file keeps the decisions worth knowing later.
The evidence stays reachable in the history of the `release/0.5.0` merge:
`git log --all -- .superpowers/sdd/0.5.0/lanes/<lane>/` and `git show <sha>:<path>`. The coordinator's ledger for this
run (entries dated 2026-11-03 and 2026-11-04) is `.superpowers/sdd/0.4.0/progress.md`, reachable the same way. Lane
branches are `lane/0.5.0-<lane>`; the spikes are `spike/0.5.0-memory`, `spike/0.5.0-unbounded-read-2` and
`spike/0.5.0-workload`.

Companion documents: the morning report `2026-11-04-0.5.0-morning-report.md`, the plan
`docs/superpowers/plans/2026-11-03-sharpit-0.5.0/PLAN.md`, the spec `docs/superpowers/specs/2026-11-03-sharpit-0.5.0-design.md`
(§13 owner's calls, §14 deviation log, §15 council round 1 resolution) and `docs/reference/PARITY.md`.

## Rulings

- **BENCH-0.4.0 database-error gate: signed off by the owner through the 2026-11-04 release authorisation.** The
  swallowed-exception gate now fails a PEP 249 database error (matched by class name) handled by a broad `except` that
  neither re-raises nor logs, widening 0.4.0 spec §5.5 F1. The review's known limits stay: the class-name match can
  false-alarm at HIGH on a non-database exception named `DataError` or `InternalError`, and misses driver exceptions
  with other names. CHANGELOG states the change.
- **Advisor status vocabulary:** rule results use BootUI's `VIOLATION`, `PASS`, `SKIPPED`, `ERROR`. `sharpit-report/1`
  (`PASSED/FAILED/UNKNOWN/SKIPPED`) is unchanged.
- **Pre-scan parity (O2):** provisional no; panels with an empty post-scan golden are reported `unverified (post-scan)`.
- **`engine/sqla/` package (O6):** yes, as a move-only commit after council. AGENTS.md architecture rule 4 now names the
  package as the gatekeeper.
- **Pentesting and Wave C (O8):** no. **0.4.0's "0.5.0" list (O9):** moved to 0.6.0.
- **Overhead budgets:** never raised. A lane failing only load-sensitive budgets is accepted with a paired lane-versus-base
  ruling (`budget_ruling.sh`), or a perf audit when the lane is on the measured path. Examples: R-transactions 11.9 us
  median against 30 us; F5b 1 of 3 runs against base 1 of 3. P-0.4.1 was not accepted on lane 1/3 versus base 0/3 until
  a perf audit ran.
- **Gate refusals handled by `--allow-path`, each logged:** `tests/fastapi/test_capture_overhead.py` for
  B-security-logs (the new panel's `CAPTURE_PANELS` line, budget value untouched), `tests/test_safety_matrix.py` for D2's
  four base-route ROWS, `src/sharpit/engine/tool_dispatch.py` for D4, `scripts/dev/lane_gate.py` for T-suite-speed
  coordinator commits. Red replay and the full rerun still ran each time.
- **T-suite-speed:** the local full suite runs at `-n 8` (AGENTS.md and `skills/check` say so); CI keeps `-n auto`.
  `tests/test_durations.json` was not refreshed: CI shards read `tests/shard_weights.json` (`tests/_shard.py`).
  PS-007 (the `install()` sqlite scan, in `src/`, safety-adjacent) stays out of the lane.
- **R-fastapi-security:** the floor-FastAPI scopes test was a broken test (fake `Dependant` shape); deleted, superseded by
  a real-floor pin (0b3f586), recorded in a `Historical SHA` row.
- **V-unverified, U20, T-unbounded-read-2, W-workload, push:** owner-only calls O1, O3, O4, O5, O7 and the push half of
  O10. Lane branches were not pushed.

## Policy changes

- `AGENTS.md`: version 0.5.0; `src/sharpit/engine/sqla/` in the layout; rule 4 names the package; local full suite at
  `-n 8`.
- `skills/release` step 4 names `tests/test_packaging.py` (it pins the version literal and its name); `skills/check`
  uses `-n 8`; `skills/sharpit` updated for 0.5.0.
- `scripts/dev/lane_gate.py` generalised to the 0.5.0 lane rules (F5-gate): council check reads the integration copy and
  last verdict, plan files are protected, a skipped must-cover test needs its flag, dependency changes are allowed only
  in the test extra. Its read cache is repo-free (T-suite-speed).
- The briefs' `COMMON.md` gained the gate's evidence-table rules (`Verdict: APPROVE` casing, a plan that names its
  must-cover tests, full SHAs only from `git rev-parse`).
- Spec §14 gained the 0.5.0 deviation rows (CLI-only advisor scans, config source scan, security-logs caps, MySQL
  drivers untested, `RAPI-VER-007` skipped, and others); the `beans` exemption row was removed when R-fastapi-security
  landed.

## Process lessons

| Lesson | Evidence | Mechanism |
|---|---|---|
| A side base built by cherry-picking a merge commit duplicated a 115-line block in `sqla.py` and tripped the code-shape ratchet | P-0.4.1, fixed in 693e402 | branch from the merge commit itself |
| Reds go invalid when a lane keeps editing shared helpers after the red commit | six lanes refused at the gate | rows moved to `Historical SHA` with mutation proofs; the last fix committed test-first |
| A claimed mutation proof was not proven until the coordinator re-ran it | T-unbounded-read identity test | coordinator re-runs the exact mutation |
| The version bump broke `tests/test_packaging.py`; the lowest-direct aux found it | T-suite-speed session | `skills/release` step 4 |
| Test-code leaks across tests looked like lane failures | transactions listener removed, context table never cleared | coordinator fix, 889 passed at `-n 0` and `-n 4` |
| A conftest import clash and a 60 s per-test timeout killed xdist workers | patch-targets scan takes 50 to 59 s alone | timeout 300 s; `TIMING_MODULES` read through `ast` |
| Writing logs inside the tree made the side-effect guard report 343 false errors | release suite run | keep logs outside the tree |
| A `sed` edit corrupted a brief with NUL bytes | workload spike launch | write briefs fresh with the Write tool |
| Subagents could not write `findings.md` | harness refusal | the coordinator writes lane evidence from the report |
| Machine-wide process exhaustion produced `STATUS_DLL_INIT_FAILED` (0xC0000142) | lowest-direct run | rerun when quiet |
| Paired A/B beat single runs: the 444 s suite baseline was mostly contention | T-suite-speed | `-n 8` default |

## Release council, 2026-11-04

The owner authorised the release when all green and verified, which also signed off the BENCH U1 widening. The high-tier
council ran on the whole `src/` diff after every lane gate had passed. Claude and Gemini found the same blockers independently,
none caught by a lane gate, CI or the release check:

| Finding | Severity | Fix |
|---|---|---|
| Raw secret in `route` under a parameterised mount | Critical | route walks Mount templates |
| `import sharpit` needed FastAPI | High | lazy, degrading import; subprocess test |
| `PRAGMA query_only` on a connection the host shares | High | sharing pools refused before checkout |
| Security-log `principal` unmasked, filtered raw | High | masked at store time |
| MySQL literals survived normalisation | High | MySQL mode in `mysql_query_text` |
| `activity`, `exceptions`, `sql-trace` dropped 2.2.0 keys; `sql-trace` timestamps were ISO | High | keys emitted, epoch ms, populated parity tests |
| BootUI wording in `architecture` output | High | renamed |
| Self-comparing conformance check; goldens with no live call | Medium | meta-test: each golden has a live parity call |

Sonar reported 65 new smells on the PR; all were fixed with no `NOSONAR`. `/code-review xhigh` found 8 defects in the suite-speed
lane's gate and test code, also fixed. `typeCounts` was ruled against BootUI's source: `JournalActivityFeed` merges per row, so
it is not pre-filled.

Lesson: lane gates prove a lane against its plan. They do not prove the release against the contract. The whole-diff council
belongs before the release check, not after it, and a contract rule needs a test that reads every golden.
