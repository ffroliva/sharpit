the 0.7.0 lanes (2026-11-18 to 2026-11-19), so they outlive the working notes. A default taken is reversible: its
deviation row in `docs/reference/matrix-updates/` says so.

## Moved to the next release

Each with its reason in PLAN.md ("Deferred to the next release"):

- A2, observed transaction boundaries: functionally complete on its branch, but the transaction listener pair went
  from 10.4 µs to 26-28 µs median against a 30 µs budget, over it under load; a budget is never raised.
- B1's `paged-without-order`: BootUI's check rests on its SQL row-limit and shape analysis, which sharpit has not
  ported; a pattern approximation misreported under default masking.
- W0 live goldens, B2-B7, D1-D4, D6, E0 (#207): as recorded in PLAN.md.
- The capture middleware's probe-header strip and the size of `CaptureMiddleware.__call__`: they touch a trust check
  and need byte-identical gate corpora before and after.

## Defaults taken (reversible)

- #66: a swallowed exception is keyed by its content hash (`<path>:<scope>:<Type>#<8 hex>[.n/m]`); an entry in the
  earlier line-keyed form warns and no longer dismisses.
- #65: an advisor that read part of an application is `PARTIAL`; a rule error, an unread router or handler, and an
  errored scan stay `UNKNOWN`. The `sharpit-report/1` status enum widens.
- #67: the report states the basis on which the REST API advisor found the application.
- A3: the project root for SEC-STATIC-001 is the nearest ancestor of the application package that holds a build file,
  never the working directory; the closest Ruff configuration wins.
- A4: BootUI's incomplete PostgreSQL relation-inventory diagnostic is not reported until a catalog observes the signal.
- A5a: the request-profile timeline tie-break does not apply (sharpit's request profile has no journal timeline).
- A7: a failure while stamping the response still records the exchange.
- B1: SQL in findings is described by statement shape, so masking never hides the rest of a sentence; distinct
  statement readings are cached (1,024 entries) to keep the full-journal report within its budget.
- Command-line client: command paths follow BootUI exactly; `argparse` replaces picocli; `--fail-on` follows BootUI
  where it differs from the pytest gate (INFO findings, an ERROR scan status); `--fail-on` on `get_exceptions` is a
  usage error, since sharpit records no caught-in-code evidence; plain calls read the whole response body and the
  `ci`-only bounded calls are not ported.
