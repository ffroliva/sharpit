# sharpit 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Run `/sharpit:status --feature 0.3.0` for the next unchecked step.

**Goal:** `pytest --sharpit` turns a test run into findings a CI job can gate on (queries per test, N+1, swallowed
exceptions, advisor findings, and `unknown` instead of a quiet pass), with a published JSON report and JUnit XML; the
console also traces raw `sqlite3`.

**Architecture:** A framework-free finding contract (`engine/advisors/findings.py`, `registry.py`) that the REST API
advisor moves onto. One SQL event path (`engine/sources/dispatch.py`) fed by the SQLAlchemy listeners and a new
`sqlite3.connect` swap (`engine/sources/sqlite.py`), routing to console contexts and to an optional test-session sink.
The sink, gates, status rules and report writers live in `engine/testsession/` (pure, testable without pytest); the
pytest plugin (`src/sharpit/pytest_plugin/`) is a thin adapter of hooks, options, marker and xdist plumbing.

**Tech Stack:** Python ≥ 3.12, stdlib `sqlite3`, `contextvars`, `logging`, `json`, `xml.etree.ElementTree`, `hashlib`,
`gc`; pytest ≥ 8 (plugin only, never a runtime dependency), pytest-xdist (test extra, already present), `pytester`;
`jsonschema` joins the `test` extra for the schema test. uv, ruff, pyright strict.

**Spec:** `docs/superpowers/specs/2026-11-01-sharpit-0.3.0-design.md` (rev 4 or later, "spec" below). The MVP and
0.2.0 specs still hold. BootUI (read-only reference) at `C:\development\github\boot-ui`. Issues: #19 (P1), #20 (P2),
#21 (P3), #22 (P4), #23 (P5), report contract #18.

**Predict / scenario:** replaced for this release by the hardening table (spec §9, rows A1-A8 and B1-B8, which are
the scenario must-cover list) and three `llm-council --tier high` rounds on the spec (spec §15, Rev 3 and Rev 4).

## Global Constraints

- Runtime deps stay exactly `starlette` and `packaging` (`tests/test_packaging.py`). `pytest` is imported only under
  `src/sharpit/pytest_plugin/`; `sqlite3` only in `src/sharpit/engine/sources/sqlite.py`. Both become rows in
  `tests/engine/test_import_boundary.py` (`GATEKEEPERS`) and AGENTS.md rule 4, in the task that adds the module.
- `engine/` never imports `sharpit.pytest_plugin` (add `"sharpit.pytest_plugin"` to `ADAPTERS` in the boundary test and
  to AGENTS.md rule 2, Task 8).
- **Inactive adds nothing.** Without `--sharpit`, a plain pytest run leaves `sqlite3.connect` the stdlib function, no
  SQLAlchemy listener, no log handler, no contextvar set, no file. Without the plugin's sink, `install()` records
  nothing about the app.
- **No secret in a report.** No bound parameter value ever reaches the session sink's facts. SQL is normalised then
  masked; every app string goes through the report masker (`Masker` built from default `SharpitSettings`, whatever
  `SHARPIT_EXPOSE_VALUES` / `SHARPIT_MASK_SECRETS` say).
- **Gates count, never time.** No gate reads a duration.
- Every hook catches its own errors: a broken sharpit hook costs a missing fact and one warning, never a changed query
  result, a changed exception type or a crashed test session. Each task that adds a hook adds its "hook raises" test.
- JSON keys: every key emitted, nulls kept, camelCase, epoch ms. The report keys are exactly spec §7.1.
- Ported tests cite their source: `# ported: RestApiScannerTests.noControllersIsConfirmedEmpty`; derived ones
  `# derived: <reason>`. Each hardening row's test carries the row id in its docstring (`"""B6: ..."""`).
- **A red is an assertion, never a crash.** Every task's Step 1 begins by adding each new module, class and function
  of its Produces block as a stub with the final signature (body `raise NotImplementedError` or a neutral return such
  as `[]`/`None`), and new keys as absent; then the tests are written; Step 2's expected failure is the named
  assertion. An `ImportError`, `AttributeError` or collection error in Step 2 means the scaffold is incomplete.
- One condition per assert (ruff `PT018`). Test basenames unique across `tests/`. No module under `src/` over 1000
  lines; complexity baselines (`tests/complexity_baseline.json`) only go down.
- Commits: conventional prefix, explicit `git add` paths, **no AI attribution of any kind**. No push, no stash (WIP
  commits instead), no merge to `main`. Each lane works only in its own worktree.
- Any command that may run longer than ~8 s runs in the background (Claude: `run_in_background`; Codex/agy: detached
  with `timeout 900 ... > run.log 2>&1 &`, then poll the log). Never more than `-n 4`.

**Commands.** Targeted: `uv run --no-sync pytest -q <paths>`. Full gate (background): `uv run --no-sync ruff check &&
uv run --no-sync ruff format --check && uv run --no-sync pyright && uv run --no-sync pytest -q -n 4`. UI (from `ui/`):
`npm test`, `npm run check`, `npm run build` (commit `src/sharpit/ui/static`).

## Review Focus

1. **A secret reaching a report file** through an exception message, a route path, an SQL literal or a vendor token as
   a positional parameter, under `SHARPIT_EXPOSE_VALUES=FULL` or `SHARPIT_MASK_SECRETS=false`. Expect: never. Pinned in
   Task 7 (`test_report_corpus_*`, three settings variants).
2. **A run that sees nothing and passes.** No source attached; SQL only through an untraced driver; everything
   unattributed; an early `from sqlite3 import connect`; an app installed before its routes were included; logging
   reconfigured mid-test. Expect `unknown`. Pinned in Task 6 (`test_status_*`) and Task 8 (`pytester` cases).
3. **A plain `pytest` run changed by installing sharpit.** Expect: byte-for-byte the same behaviour. Pinned in Task 8
   (`test_plain_run_untouched`, B1).
4. **The wrong test blamed.** Lifespan workers, threads, reruns, `--dist each`, async tests. Expect: only same-test,
   same-attempt facts gate. Pinned in Task 6 (`test_attribution_*`) and Task 8 (`test_lifespan_worker_unattributed`,
   `test_async_tests_attributed`).
5. **A host query changed by tracing.** Errors re-raised unchanged, `check_same_thread` intact, caller factories kept,
   no double count with SQLAlchemy (sync and aiosqlite). Pinned in Task 5.
