# F0 Console Contract — Predict & Scenario Analysis

## 1. Predict (`/sharpit:predict`)

### Architect

Today `src/sharpit/fastapi/adapter.py` (`SharpitMount` lines 61–81, `GuardMiddleware` lines 91–153) and `src/sharpit/fastapi/routes/` (38 sibling modules plus `routes/__init__.py` lines 1–716) combine Starlette routing, duplicate-header denial, header joining, static asset serving, and SSE framing with framework-free collector logic that already lives in `src/sharpit/engine/`. Moving the active HTTP console pipeline (`ConsoleRequest`, `ConsoleResponse`, `ConsoleStream`, `RouteSpec`, `ConsoleCall`, and `Console.handle`) into `src/sharpit/engine/console/` honors Architecture Rules 1 and 2 in `AGENTS.md`: `engine/` remains free of `fastapi`, `starlette`, `flask`, and `werkzeug`, while `sharpit/fastapi/` and `sharpit/flask/` act as thin protocol translators over ASGI and WSGI. The host-specific boundaries—inactive 404 pass-through (`_not_found` in `src/sharpit/fastapi/adapter.py:234-239`), ASGI WebSocket refusal (`adapter.py:111-114, 236-238`), in-process HTTP probing (`HostProbe` over `src/sharpit/engine/probe.py:221-370` and `src/sharpit/fastapi/pentesting_probe.py:46-57`), request-scoped event-loop discovery (`HostLoopProvider` in `src/sharpit/engine/spi.py:10-13` and `src/sharpit/engine/tools04/hostloop.py:14-37`), capture hook failure reporting (`CaptureHooks` in `src/sharpit/engine/capture/__init__.py:21-24`), and framework introspection (`AppIntrospector` in `src/sharpit/engine/spi.py:99-104`)—stay cleanly separated. Replacing the ASGI `scope` dictionary reads in `overview_dto` (`src/sharpit/engine/collectors/overview.py:19-23`), `CallContext` (`src/sharpit/engine/tools.py:104, 409`), `McpServer.handle` (`src/sharpit/engine/mcp.py:387-418, 450-557`), and `pentesting._scan` (`src/sharpit/engine/tools04/pentesting.py:32`) with typed request fields ensures no WSGI adapter ever fabricates a fake ASGI `scope`.

**Vote:** GO WITH CONDITIONS — all `scope` dictionary reads in `overview.py`, `tools.py`, `mcp.py`, and `tools04/pentesting.py` must be replaced by typed request fields on `ConsoleCall` / `CallContext`, and every route in `ROUTES` must carry a stable `id` and `kind` (`"read"` or `"action"`) with audit hooks at both route dispatch and tool dispatch (`call_tool` in `src/sharpit/engine/tool_dispatch.py:205-221`).

### Security Engineer

The safety model (`AGENTS.md` Safety Rules 1–6) requires executing the exact guard and panel-access sequence on every active request under the mount before route matching (`GuardMiddleware._decide` in `src/sharpit/fastapi/adapter.py:125-153` and `decide_guard` in `src/sharpit/engine/guard.py:373-401`), while keeping an inactive console (`not activation.enabled`, `src/sharpit/engine/activation.py:14-18`) completely absent (the host renders its own 404 without sharpit security headers, `src/sharpit/fastapi/install.py:324-331`, `adapter.py:234-239`, `tests/fastapi/test_install.py:49-62`). Three WSGI and request-handling invariants are critical:
1. **Duplicate and comma-joined security headers:** Today `GuardMiddleware._decide` (`src/sharpit/fastapi/adapter.py:128-131`) denies multi-tuple `host` with `403 {"error": MESSAGE_DISALLOWED_HOST}` (`src/sharpit/engine/guard.py:38-40`) and multi-tuple `origin` or `sec-fetch-site` with `403 {"error": MESSAGE_CROSS_SITE}` (`guard.py:41`), and then joins headers with `", "` and `"; "` for `cookie` (`adapter.py:132`). In PEP 3333 WSGI, servers such as Werkzeug fold duplicate headers with `","` (no space) into `environ["HTTP_<NAME>"]`. Furthermore, when an HTTP/1.1 client sends an absolute-form request target (`GET http://localhost/sharpit/api/overview HTTP/1.1`), Werkzeug overwrites `environ["HTTP_HOST"]` with the URI's authority while leaving the raw target in `RAW_URI` / `REQUEST_URI`. The WSGI adapter must split comma-containing `HTTP_HOST`, `HTTP_ORIGIN`, and `HTTP_SEC_FETCH_SITE` on `","` into multiple tuples in `ConsoleRequest.raw_headers` and refuse any request under the mount whose `RAW_URI` or `REQUEST_URI` is in absolute form.
2. **Adapter-owned probe provenance:** The internal probe flag (`scope["extensions"]["sharpit.probe"]` in `src/sharpit/fastapi/adapter.py:144` and `src/sharpit/engine/probe.py:260`) is refused by `decide_guard` (`src/sharpit/engine/guard.py:377-378`). A WSGI `environ` key must never be allowed to set `ConsoleRequest.is_probe`.
3. **Blanket exception boundary:** `Console.handle` must catch every exception—mapping `BadRequest` (`src/sharpit/engine/paging.py:11-12`) to `400` (`src/sharpit/fastapi/adapter.py:222-223`), `AdvisorViolationError` (`src/sharpit/engine/advisors/retention.py:19-25`) to `exc.status` (`src/sharpit/fastapi/routes/__init__.py:558-559`), and any other `Exception` to a masked `500` JSON response with `security_headers("api")` (`src/sharpit/engine/headers.py:20-32`)—so an uncaught exception never escapes into Werkzeug's interactive `DebuggedApplication` debugger under `flask run --debug`.

**Vote:** GO WITH CONDITIONS — keep the 403 duplicate-header denials and `", "` / `"; "` header joining from `adapter.py:128-132`, split comma-folded WSGI security headers and reject absolute-form `RAW_URI` / `REQUEST_URI` in the WSGI adapter, keep `is_probe` adapter-owned, and catch all exceptions inside `Console.handle`.

### FastAPI Host Developer

FastAPI applications depend on `sharpit.install(app)` never starving the host's AnyIO worker threadpool (`anyio.to_thread.current_default_thread_limiter()`) and never blocking the host event loop. In `src/sharpit/fastapi/routes/__init__.py`, `GET /sharpit/api/threads` (`thread_dump`, `routes/__init__.py:505-508`) runs on the event loop so `_tasks` (`src/sharpit/engine/collectors/threads.py:161-182`) can inspect `asyncio.all_tasks()` directly (`running is loop`) without spawning threads (`tests/fastapi/test_threads_api.py:77-90`). Meanwhile, filesystem-scanning reads such as `GET /sharpit/api/config` (`routes/__init__.py:150-154`) run off the event loop so a slow first package scan cannot stall concurrent console requests (`tests/fastapi/test_concurrency.py:19-50`), and tool dispatchers (`POST /sharpit/api/mcp` at `routes/__init__.py:615-629` and `POST /sharpit/api/cli/tools/{tool}` at `routes/__init__.py:665-672`) capture `_RequestHostLoopProvider(asyncio.get_running_loop())` (`routes/__init__.py:50-55`) and run `McpServer.handle` / `cli_invoke` off the loop because `wait_on_host_loop` (`src/sharpit/engine/tools04/hostloop.py:19-37`) blocks on `future.result(timeout)`. Supporting `async def` handlers alongside sync `def` handlers (which run on sharpit's lazy `DaemonExecutor(4, thread_name_prefix="sharpit-console")` from `src/sharpit/engine/daemon_executor.py:14-35` unless marked `on_loop=True`) preserves both invariants without touching the host's AnyIO threadpool. On Flask, auto-activation must require a verified reloader signal (`flask run --reload`, `flask run --debug` without `--no-reload`, `WERKZEUG_RUN_MAIN=true`, or `gunicorn --reload`); `FLASK_DEBUG=1` without reload must not activate the console.

**Vote:** GO WITH CONDITIONS — run sync `on_loop=False` handlers on sharpit's `DaemonExecutor`, keep `wait_on_host_loop` callers off the host event loop, and require a verified reloader signal for Flask activation.

### Parity Auditor

The F1 HTTP response corpus gate (`PLAN.md:73, 225-236`) requires byte-for-byte identity on FastAPI before and after every F2 batch. That means:
- The inactive path stays in the adapter (`_not_found` raises `HTTPException(404)` in `src/sharpit/fastapi/adapter.py:234-239`) with no security headers.
- Guard plus method-based panel access (`decide_guard` and `_panel_access` in `src/sharpit/engine/guard.py:339-355, 373-401`) run before route matching, so an unknown path under a disabled panel answers `403` (`PANEL_ACCESS_DENIED`), not `404`.
- Response headers come from `security_headers(kind)` (`src/sharpit/engine/headers.py:20-32`) driven by `RouteSpec.response_class` (`"api"`, `"shell"`, `"asset"`), preserving `Permissions-Policy`, `Pragma: no-cache` on `"api"` and `"shell"`, and `Cache-Control: public, max-age=31536000, immutable` without `Pragma` on `"asset"`.
- `POST {api}/auth/session` (`src/sharpit/fastapi/routes/__init__.py:123-130`) uses `ConsoleCall.trusted` to emit `Set-Cookie: SHARPIT_SESSION=...` (`SESSION_COOKIE` in `src/sharpit/engine/guard.py:24`) only when `not call.trusted and ctx.token`.
- Dropping the pre-guard ASGI comma rule (and splitting comma-folded `HTTP_HOST`, `HTTP_ORIGIN`, and `HTTP_SEC_FETCH_SITE` in the WSGI adapter instead) avoids changing today's FastAPI corpus on single-tuple `Sec-Fetch-Site` or untrusted-peer requests.

**Vote:** GO — enforce the F1 corpus gate after every F2 batch and verify `ROUTES` against `adapter._routes(ctx, app)` (`src/sharpit/fastapi/adapter.py:245-255`).

### Skeptic

The main risk in serving SSE streams (`src/sharpit/engine/capture/streams.py:1-228` and `src/sharpit/fastapi/sse.py:1-77`) on WSGI is worker-thread exhaustion and subscriber leaks on disconnect. Inspecting `src/sharpit/engine/capture/streams.py` as it exists today shows that `_Ticker` (`streams.py:48-96`), `Subscription` (`streams.py:99-110`), `LineSubscription` (`streams.py:113-157`), and `_Hub` (`streams.py:160-181`) are already built around per-subscriber `asyncio.AbstractEventLoop` instances woke via `self._loop.call_soon_threadsafe(self._wake)` (`streams.py:67`). Requiring standard-library `asyncio` across adapters and running each WSGI stream on a per-request private `asyncio.new_event_loop()` on the serving WSGI worker thread avoids duplicating `_Ticker` and `LineSubscription`, spawns zero extra threads, bounds each stream to `stream_max_seconds` (`3.0` s in `src/sharpit/settings.py:104`), and detaches subscribers deterministically via `frames.aclose()` inside PEP 3333's `close()` hook. Capacity on WSGI must use an explicit setting with a conservative default (`4`, or `0` to disable streaming) rather than parsing launcher flags like `gunicorn -t` (which is `--timeout`, not `--threads`).

**Vote:** GO WITH CONDITIONS — use standard-library `asyncio` with a per-stream private loop on WSGI, an explicit WSGI stream slot setting (never inferred from `sys.argv`), and idempotent `close()` cleanup.

### Verdict: GO WITH CONDITIONS

1. **Preserve FastAPI bytes exactly:** Keep inactive 404 and WebSocket refusal in the adapter, run `decide_guard` (including method-based `_panel_access`) before route matching, join headers with `", "` and `"; "` for `Cookie`, apply `security_headers(route.response_class)` (`"api"`, `"shell"`, `"asset"`), and drop the pre-guard comma rule on ASGI in favor of WSGI adapter splitting.
2. **WSGI security parity:** In the WSGI adapter, split comma-joined `HTTP_HOST`, `HTTP_ORIGIN`, and `HTTP_SEC_FETCH_SITE` on `","` into multiple tuples, refuse absolute-form `RAW_URI` / `REQUEST_URI` under the mount with `403 MESSAGE_DISALLOWED_HOST`, and never read `is_probe` from `environ`.
3. **Exception containment:** Catch all exceptions in `Console.handle` (`BadRequest` -> `400`, `AdvisorViolationError` -> `exc.status`, any other `Exception` -> masked `500` JSON with `security_headers("api")`).
4. **Loop and executor discipline:** Support `async def` and sync `def` handlers; run sync `on_loop=False` handlers on sharpit's `DaemonExecutor(4, thread_name_prefix="sharpit-console")`; never run `wait_on_host_loop` callers on the host event loop.
5. **Verified Flask reloader signal and explicit WSGI stream cap:** Require an explicit reloader signal (`flask run --reload`, `flask run --debug` without `--no-reload`, `WERKZEUG_RUN_MAIN=true`, `gunicorn --reload`; never `FLASK_DEBUG` alone), and gate WSGI streams with an explicit slot limit (`4` default, `0` off).

## 2. Worst-Case Trace (`/sharpit:scenario`)

Trace of real failure modes if the console contract were implemented without these safeguards:

1. **Werkzeug `","` header folding and absolute-form `RAW_URI` host overwrite (`src/sharpit/fastapi/adapter.py:128-131`, `src/sharpit/engine/guard.py:322-336, 385-392`):**
   When two `Sec-Fetch-Site: same-origin` and `Sec-Fetch-Site: cross-site` headers arrive on WSGI, Werkzeug folds them with no space into `environ["HTTP_SEC_FETCH_SITE"] = "same-origin,cross-site"`. Without comma-splitting in the WSGI adapter, `len(values.get("sec-fetch-site", ()))` is `1` and `facts.headers.get("sec-fetch-site", "").casefold() == "cross-site"` (`guard.py:323`) is `False`, letting a cross-site request bypass the check that FastAPI refuses with `403 MESSAGE_CROSS_SITE` (`adapter.py:130-131`). Similarly, if a client sends `GET http://localhost/sharpit/api/overview HTTP/1.1` with header `Host: evil.example`, Werkzeug overwrites `environ["HTTP_HOST"]` with `"localhost"` while leaving `http://localhost/sharpit/api/overview` in `environ["RAW_URI"]` / `environ["REQUEST_URI"]`; without the absolute-form URI refusal in the WSGI adapter, the forged request-line authority would bypass the `Host` allow-list check (`guard.py:385-390`).
2. **Uncaught exception triggering Werkzeug's interactive debugger under `flask run --debug` (`src/sharpit/fastapi/install.py:360`, `src/sharpit/fastapi/adapter.py:222-231`):**
   On FastAPI, Starlette's `sub_app` registers `exception_handlers={404: _json_http_error, 405: _json_http_error, BadRequest: _bad_request}` (`install.py:360`). If an unexpected exception escaped `Console.handle` into a Flask host running `flask run --debug`, Werkzeug's `DebuggedApplication` middleware would catch it and render an interactive HTML traceback with local variables and without `security_headers("api")`. Catching every `Exception` inside `Console.handle` guarantees a masked `500` JSON response with `security_headers("api")`.
3. **Deadlock when a tool caller runs on the host event loop (`src/sharpit/engine/tools04/hostloop.py:19-37`, `src/sharpit/fastapi/routes/__init__.py:615-629, 665-672`):**
   `wait_on_host_loop` (`hostloop.py:19-37`) schedules a coroutine on the request's event loop via `asyncio.run_coroutine_threadsafe(coro, loop)` and blocks on `future.result(timeout)`. If `POST /sharpit/api/mcp` or `POST /sharpit/api/cli/tools/{tool}` ran `McpServer.handle` or `cli_invoke` synchronously on the ASGI event loop thread instead of offloading to a worker thread, `future.result(timeout)` would block the event loop thread from running the scheduled coroutine until `FutureTimeoutError` fired (`504` / `-32002`).
4. **Leaked `_Ticker` subscribers and `StreamSlots` on WSGI SSE disconnect (`src/sharpit/engine/capture/streams.py:48-96, 160-181`, `src/sharpit/fastapi/sse.py:36-76`):**
   When `change_events` (`streams.py:221-228`) or `log_events` (`src/sharpit/engine/capture/logtail.py:98-105`) runs, `stream.subscribe(asyncio.get_running_loop())` adds a `Subscription` / `LineSubscription` (`_Ticker`) to `_Hub._subscribers` (`streams.py:162, 175-177`). Unsubscription happens in the `finally: subscription.close()` block of `change_events` (`streams.py:227-228`) and `log_events` (`logtail.py:104-105`) when `_frames` closes the async generator (`await aclose()` in `src/sharpit/fastapi/sse.py:48-51, 68-69`). On WSGI, if `WsgiEventStream.close()` did not run `loop.run_until_complete(frames.aclose())`, close the private event loop, and call `ConsoleStream.close()`, each disconnected browser tab would leak one `StreamSlots` count until all subsequent streams returned `503 {"error": "Too many concurrent sharpit streams"}` (`sse.py:24, 75-76`).
