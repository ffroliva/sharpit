# Flask route model

The F1 adapter exposes Flask route metadata to sharpit's pytest advisor. Flask remains a test-only dependency, with
2.3.3 as the supported floor and Flask 3.x as the current test target. The adapter reads the public `url_map` and
registered rules; it does not call views or inspect blueprint internals.

## Mapping

| Flask source | sharpit representation |
|---|---|
| `app.import_name` | `AppInfo.title` |
| Flask distribution metadata | `AppInfo.framework_version`; `docs_url=None` |
| Each `app.url_map.iter_rules()` rule | One `RouteInfo`, in registration order |
| `Rule.methods` | Sorted effective methods, including Werkzeug-added `HEAD` and `OPTIONS` |
| `Rule.rule` | Path with `<name>` and `<converter:name>` rendered as `{name}`; slash spelling is preserved |
| Registered view callable | `module:qualname` handler identity, read without calling it |
| `Rule.endpoint` | Route name |
| No dependency-provider graph | `providers() == []` |

`RouteInfo` cannot carry `strict_slashes`, subdomain or host constraints, converter validation semantics, blueprint
provenance, explicit-versus-automatic methods, response metadata, or media types. The adapter preserves the written
path, reports `host=None`, and reports unavailable response and media metadata as `None`. It does not infer semantic
equivalence between routes with different slash or host behavior.

An unreadable URL map is distinct from a confirmed empty map: route inspection returns `None` when the map cannot be
read, and an explicitly selected app is reported as `UNKNOWN`. Unreadable rule fields are skipped without evaluating
descriptors. Flask discovery checks already-loaded `sys.modules` entries; it does not import Flask. The Flask adapter
is loaded only after a Flask app is selected.

BootUI 2.5.0 has no Flask route model. Flask-specific route metadata and safe static reads have no BootUI parity
counterpart or shared contract key.
