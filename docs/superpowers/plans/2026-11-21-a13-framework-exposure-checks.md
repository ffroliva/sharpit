# A13 Framework-Exposure Pentesting Checks Implementation Plan

> Run `/sharpit:status --feature a13-framework-exposure-checks` for the next unchecked step. Complete one task at a time and run `/sharpit:check` before each commit.

**Goal:** Add the BootUI v2.5.0 framework-exposure checks that have a FastAPI/Starlette equivalent (PT-A05-041 documentation or developer console exposed, PT-A05-044 forwarded headers trusted) to the explicitly invoked pentesting scan, and record every other framework-metadata check as not applicable, adapted elsewhere or owned by another lane, by explicit id and with its reason.

**Scope:** FastAPI/Starlette only. The pentesting scan as a whole (route, MCP tool, CLI command, probe) is wired to the FastAPI adapter; the Flask adapter has none of it, so Flask rows are `pending`.

**Architecture:** The framework-free pentesting engine gains one value object (`FrameworkEvidence`) and the two rules that evaluate it. The FastAPI adapter builds that evidence from the application's own route table and middleware facts by attribute reads, as the Security and Routes panels already do; nothing is called and no request is sent. The scan action (the same function that serves the route, MCP and CLI) reads `routes()` once and `security_facts()` once, only after `run_probe` has acquired the single-flight and returned (a busy or refused scan reads neither), shares the facts read with A12, and builds the evidence; GET report reads never do. Unreadable, unrecognised or truncated evidence is reported as a gap and makes the scan partial, never a clean result; when the security facts are unavailable (a non-FastAPI host, a failed read) or carry any limitation, the scan carries BootUI's fixed configuration gap and is partial. Masking follows A11's fragment rule: `PentestingService.scan` receives the required keyword-only `masker`, builds `echo = make_echo(masker)`, and the rules pass only the host-chosen fragments (documentation route paths and mount paths) through `echo`, before the evidence is sanitised and cut at 240 characters. Fixed BootUI text, gaps and limitations are never masked. `echo`, `make_echo` and the evidence sanitiser live in one shared module, `engine/collectors/pentesting/echo.py`, the module A12's Task 0 creates (a move out of `cors.py`); the CORS rules, the cookie rules and this lane import it.

**Tech Stack:** Python 3.12+, existing `RouteInfo` and `SecurityFacts` introspection, pytest, BootUI-derived fixtures.

**Review gate:** Complete the required high-tier review of this plan and record its disposition before implementation begins.

## Decisions

1. PT-A05-041 and PT-A05-044 are emitted as pentesting findings with BootUI's ids, because the ids are BootUI's report, ordering (`PentestingCheckRegistry.java:35-105`) and dismissal contract. BootUI's Spring advisor has no equivalent rule (`SecurityRules.java` mentions forwarded headers only in TLS text), so there is no BootUI pairing to copy; the pair exists only in its Quarkus advisor. `SEC-FAPI-002` and `SEC-FAPI-003` are sharpit rules with different triggers (secured routes; `trusted_hosts="*"`), the two advisors are disjoint (`registry.py:76-82`) so no panel shows both, and pentesting has no pytest gate (`assess=None`). The security rules are not changed and a test pins their ownership. This overrules the earlier recommendation to reuse the advisor rules instead of adding pentesting findings.
2. The documentation routes are identified by the registered handler (module and qualified name), not by path and not by the configured URL attributes (see the scenario's worst-case trace). The path is only what the finding reports. ReDoc is found the same way, as a registered route; no configured ReDoc URL is read.
3. Evidence exists only in the scan action. A report read returns the cached or initial report and calls none of `routes()`, `app_info()` or `security_facts()`. The action reads `routes()` and `security_facts()` only after `await run_probe(...)` has acquired the single-flight and returned; a busy scan (409) or a refused scan (read-only panel, MCP or CLI off, guard, inactive console) reads neither.
4. Coverage follows BootUI's precedence (finding, hand-off or not-applicable, then indeterminate; `PentestingCheckRegistry.java:270-286`). Endpoint truncation or unreadable evidence sets `partial`, which makes A02 INDETERMINATE through the rule A11 ports when no A02 finding exists (a finding gives REVIEW first, `PentestingCheckRegistry.java:270-276`; the default FastAPI app has PT-A05-041, so the fixtures that assert INDETERMINATE use an app with no A02 finding). A07 is not made indeterminate: BootUI's A07 hand-off branch (`PentestingCheckRegistry.java:164-175, 279-281`) precedes its indeterminate branch (`:285-288`) on an adapter without Spring metadata, and sharpit's A07 is that branch. The behaviour is ported; two things differ and are one deviation row, `pentesting:exposure-coverage-a07`: sharpit's label is NOT_APPLICABLE where BootUI's is HANDOFF, and the ported truncation assertion (`PentestingScannerTests.java:754-779`, which runs with Spring metadata present and so asserts INDETERMINATE) becomes NOT_APPLICABLE. A test pins A07, A04 and A10 unchanged.
5. The security facts fail closed, in this lane and in A12 alike. When `security_facts()` is absent, raises, returns a value that is not `SecurityFacts` (A12's `read_security_facts` gives `None`), is the non-FastAPI marker, or carries any limitation, the evidence has `config_incomplete=True` (a boolean; the limitation text is never read): the scan records BootUI's fixed gap `Framework configuration evidence was incomplete.` (`PentestingAssessment.java:41-44`; one string, shared with A12 and deduplicated) and is PARTIAL, and PT-A05-044 is not reported as evaluated. Documentation is still evaluated from the route table. A missing `routes` method or an exception from `routes()` is the route-failure case: BootUI's endpoint gap, PARTIAL, A02 INDETERMINATE unless an A02 finding exists. A13's own tests assert only A13's contribution (the gap exactly once, PT-A05-041 present or absent as the routes say, PT-A05-044 absent, and PARTIAL from A13's evidence alone in `scanned_report` without session evidence), never the whole scan's status, which A12's tests own. This replaces the earlier absent-provider reading (no gap, not partial): a non-FastAPI host, a failed read and a wrapped mount all reach the adapter as the same signal (absent facts or a limitation), and the safe answer to all three is the one fixed gap.
6. `security_facts()` is read once per scan, by `read_security_facts` in `fastapi/pentesting_exposure.py`, which A12 creates (its own red-first tests cover the raising, absent and wrong-type cases) and this lane extends; the helper wraps the call in `except Exception` and degrades to "unavailable". A12 and A13 consume that one read. `SecurityFacts.limitations` text is never copied by any lane: it can carry route paths and mount labels (`introspector.py:410, 878-884`) and limitations are not masked. A12 uses only whether the facts are absent or carry any limitation (a boolean behind BootUI's fixed configuration gap), never the text. This lane reads the same boolean, `config_incomplete = facts is None or bool(facts.limitations)`, and nothing else from the limitations. A mount wrapped in a middleware instance such as `ProxyHeadersMiddleware(sub)` is recorded by the introspector only as limitation text (`introspector.py:878-882`) and has no `MiddlewareFacts`, so it is covered by that boolean and surfaces as the fixed gap, never as silence. A planted-path test pins that the text never reaches the report.
7. The middleware match requires the simple name `ProxyHeadersMiddleware` (the advisor's `simple()` helper) and the module `uvicorn.middleware.proxy_headers`; Starlette ships no such class.
8. Masking is A11's fragment rule. `evaluate(evidence, echo)` takes `echo` as a required argument (no identity default, so a caller cannot forget it). Each rule sorts and de-duplicates the raw documentation or mount paths first, then passes each one through `echo`, joins them into BootUI's evidence text, and sanitises the whole string (CR, LF and TAB runs to one space, trim, 240 characters with `...`). Under `METADATA_ONLY`, `echo` returns `[masked]` per path, so the count and order survive. The middleware class name is matched exactly (simple name plus module) and is fixed text, never echoed. Gaps and limitations are fixed strings and are not masked. Deviation row `pentesting:exposure-masking` records that BootUI masks nothing here.
9. Gaps land in `evidence.limitations`, with BootUI's gap wording (`PentestingScanner.java:260-262`; `PentestingAssessment.java:41-44`), placed before the generic trailing sentences; the scan `message` stays the fixed text of A10 (BootUI appends the gaps to its message, `:288-291`; row `pentesting:exposure-gap-placement`). `usable` is unchanged: it stays the GET probe's usability (`report.py:272`), so unavailable route evidence neither raises nor lowers it. `coverageComplete` stays False as A10 sets it. This lane has two gap strings and no standing entry of its own: BootUI's endpoint-metadata text `endpoint metadata was incomplete or exceeded the 4096-pattern inspection limit` (used alike for unavailable, truncated and unrecognised route evidence) and the shared configuration gap `Framework configuration evidence was incomplete.` (facts unavailable, a non-FastAPI host, a wrapped mount). The 20-entry cap of 240 characters (`_unique_limitations`, `report.py:433-434` on A11's branch) is counted, not assumed. Worst case that the real probe can produce (both probes rejected by Host with a truncated body and an incomplete header inventory): A10 7 entries (two incomplete reasons, the GET and OPTIONS body and header truncation notes, the missing-resource note; the timed-out note excludes truncation) plus 3 trailing statements, A11 up to 8 (six per-method gap strings, its PT-A05-073 limitation and the OPTIONS header gap), A12 1 new string (the configuration gap; its GET header gaps are A11's strings), A13 1 new string (the endpoint gap). Total 7 + 8 + 1 + 1 + 3 = 20: there is no slack. A13 therefore adds no standing entry: its statement is folded into the third trailing sentence (Decision 10), and its wrapped-mount, facts-unavailable and non-FastAPI cases reuse a string A12 already counts. The worst-case test asserts every promised statement is present and pins each lane's maximum in a count table, so a producer added anywhere fails the test until it is consolidated.
10. Mounted applications that are not Starlette applications (a WSGI app, a metrics ASGI app) and documentation served by a host's own handler (a route that is not FastAPI's own handler) are not recognised: the evidence cannot tell they exist. This is a standing limitation, folded into the third trailing statement of every scan (A10's sentence, after A12 removes its cookie words and this lane replaces the route and middleware words; Decision 9), final text `Route and middleware evidence is static: server forwarded-header flags, non-Starlette mounts and documentation served by a host's own handler are not recognised. Spring Security, JVM, servlet and Actuator checks have no Python equivalent.` (238 characters). It is a limitation, not a gap: it does not make the scan partial. It also states that server-level forwarded-header flags are not observable.

11. Pinned text; the tests compare the exact strings. PT-A05-041 keeps BootUI's id, title (`API documentation or developer console is exposed`), category, severity and confidence; its target is `Application route table` (BootUI: `Spring MVC mappings`, `PentestingChecks.java:2264-2275`) and its evidence is BootUI's template over the sorted, echoed paths. PT-A05-044 keeps BootUI's id, category (A02), severity INFO and confidence Low; its title is `ProxyHeadersMiddleware trusts X-Forwarded-* headers` (BootUI: `server.forward-headers-strategy trusts X-Forwarded-* headers`, `:2414-2447`); its target is `ProxyHeadersMiddleware` (BootUI: `server.forward-headers-strategy`); its evidence is `ProxyHeadersMiddleware enables forwarded-header handling on {where}. Trusted proxy configuration and direct network reachability were not inspected.`, where `{where}` joins with `, ` the item `the root application` (when the root stack has the middleware) and then `the mount at {echo(path)}` for each sorted, unique mount path; its recommendation is BootUI's text with the Spring and Tomcat names replaced: `This middleware is often legitimately required behind a trusted reverse proxy. Confirm the proxy strips or overwrites client-supplied X-Forwarded-* headers before they reach the application (for example through an allow-listed ingress or load balancer, or uvicorn's --forwarded-allow-ips), and that no untrusted client can reach the application directly, bypassing that proxy; otherwise any client can spoof source IP, host, and scheme, bypassing IP allow-lists and audit logging.` The finding fires for the middleware's presence alone, as BootUI's fires for `framework` or `native`; no text says that trust is unrestricted or that a trust flag was inspected. The learn-more link names uvicorn's proxy-header documentation.

## Global Constraints

- Reads have no side effects: no GET route and no read MCP or CLI tool builds the evidence, opens a socket, writes a file, changes a logger level or changes `os.environ`. The evidence is built by attribute reads inside the action; no host endpoint is called.
- Actions keep A10's gates: enablement, guard, enabled panel, non-read-only, single-flight.
- Route and mount paths reach output only through `echo`, built by `make_echo(masker)` from the required `masker` of `PentestingService.scan` (A11's wiring); no raw host value other than a masked path or the fixed middleware class name is returned, and `SecurityFacts.limitations` text is never copied into the report. This lane adds no second masker, defines no echo or sanitiser of its own (a test pins that), and does not import `Masker` through `collectors/security`. Tests prove it in `MASKED`, `METADATA_ONLY` and `FULL` with the real `Masker`.
- No claim of authorization or reachability: the evidence says the route is registered, nothing more.
- A failure, an unrecognised shape, or a truncated inventory is indeterminate and stated, never a clean result.
- `engine/` imports no `fastapi` or `starlette`; the adapter owns the handler names and the middleware module name.
- Every ported test cites its BootUI source with `# ported: <Class>.<method>`.
- Tool descriptions and `cli/tools.json` are contract text and are not edited.
- No module under `src/` exceeds 1000 lines; ratchets only go down.
- Every `test:` task is red against a wrong-value stub: the stub returns plausible wrong values so each test fails on the assertion that names the defect, never on an import error. Every stub of a function that gains the `echo` parameter has the final signature (`evaluate(evidence, echo)`), so a test never fails with a `TypeError` on the call. The masking stub returns BootUI's text with the raw sorted paths, calls `echo` never and sanitises nothing, so the planted-secret, `METADATA_ONLY`, recording-echo and sanitiser tests fail on their own assertions. Each task lists its stub and the red reason per test.
- Every pytest command in this plan is targeted and parallel: `uv run pytest -q -n 4 <files>`. The full suite is not run locally.
