# T1 per-endpoint HTTP security gate Implementation Plan

> **For agentic workers:** Run `/sharpit:status --feature t1-per-endpoint-security-gate` for the next unchecked step. Execute one task at a time; run `/sharpit:check` before every commit.

**Goal:** Add an opt-in pytest advisor that evaluates explicitly configured response expectations against HTTP requests host tests already make, and reports unobserved expectations as unknown.

**Architecture:** Keep observation and framework adapters in `sharpit.pytest_plugin/`; keep normalized facts and findings in the existing engine test-session/advisor path without importing pytest or web frameworks into the engine. Observe only requests made through an explicit pytest wrapper for the exact registered app; previous requests outside that wrapper do not count. FastAPI/Starlette and Flask adapters wrap the exact app supplied to the fixture; automatic app discovery does not imply observation. Omit sensitive values before facts are stored, and reuse existing findings, xdist aggregation, severity, report-only, baseline, terminal, JSON, SARIF and JUnit paths.

**Tech Stack:** Python 3.12+, pytest, pytest-xdist, Starlette/FastAPI and Flask test extras; existing sharpit findings and test-session reporting.

## Global Constraints

- Python `>=3.12`; runtime dependencies exactly `starlette` and `packaging`. `fastapi` and `pydantic-settings` are optional: import them only inside `try/except ImportError` or in `sharpit/fastapi/`.
- **Reads have no side effects:** no GET route and no read MCP or CLI tool of the console installed in a host application may open a socket, write a file, change a logger level or change `os.environ`.
- **Fails closed.** Inactive means every path under the mount answers 404 and reveals nothing.
- **Guard chain on every request**, in order: security headers → trusted source → Host allow-list → cross-site → token → panel access. Forwarded headers never grant trust.
- **Secrets masked** before filtering and before any output (JSON, errors, MCP, CLI). `FULL` exposure warns.
- **No side effects on reads; actions only behind BootUI's gates.**
- **Introspection is defensive**: FastAPI/Starlette internals change between versions; degrade, never crash the host.
- Dependencies point inward; `engine/` never imports pytest, FastAPI or Starlette. No module under `src/` may exceed 1000 lines.
- Port BootUI where it has a counterpart. T1 has none; do not invent `# ported:` citations or BootUI goldens. Record its explicit sharpit-only deviation in the lane matrix.
- Every defect found becomes a regression test seen red first; tests use one condition per assert. Tests follow the repository's parallel-test workflow. Never weaken tests or raise an overhead budget.

## Risk register

| Severity | Risk | Mitigation |
|---|---|---|
| Critical | Raw authorization, cookie, query or response-header values enter stored facts or an output sink | Capture names/status only; omit values and bodies before facts are created; test all report formats and exception paths with secret canaries. |
| Critical | Enabling the HTTP advisor changes app behavior, sends probe requests or activates runtime capture implicitly | Separate explicit `--sharpit-http-security` / `sharpit_http_security` opt-in; observe only requests already generated by tests; preserve exact response and middleware order. |
| High | Route metadata is mistaken for an authorization contract or unsupported observation is called a pass | Evaluate only explicit expectations; mark missing app, hidden route or unsupported wrapper unknown/partial. |
| High | FastAPI and Flask paths produce inconsistent attribution or alter test-client behavior | Normalize method, canonical route, status and header names in pytest-facing adapters; prove both adapters and an opaque-wrapper fallback. |
| High | Findings gate the run incorrectly or baselines hide unknown coverage | Use a separate advisor/rule path from `test-runtime`; reuse current xdist and report semantics; baseline only stable route/rule fingerprints and refuse partial/unknown writes. |
| High | Per-request overhead grows with payload size or report output | Never read/copy bodies or header values; bound metadata and measure observer-on/off overhead with the production pytest wrapper. |

## Task 2: Add bounded facts and explicit expectation evaluation

**Files:** `src/sharpit/engine/advisors/http_security.py` (new), advisor registration under `src/sharpit/engine/advisors/`, `src/sharpit/engine/testsession/facts.py`, `src/sharpit/engine/testsession/sink.py`, and `tests/engine/advisors/test_http_security.py` (new).

**Interfaces:** A fact contains only an optional opaque per-attempt key used for attribution, method, canonical route or unknown, status, and response-header names. The key is not a pytest node ID and is not part of finding identity. Facts are serialized through `PhaseFacts`/`TestFacts` in `engine/testsession/facts.py` and the existing sink path so xdist worker-to-controller transfer preserves them. Workers collect facts only; a controller-only hook evaluates expectations once after merging all worker facts, before report serialization. Expectations are available to that hook through `GateOptions`. Evaluation produces `HTTP-SEC-001` HIGH for missing configured headers and `HTTP-SEC-002` HIGH for unexpected configured statuses. A 500 without a status expectation is evidence only, not a finding. Distinct missing headers have distinct fingerprint identities. Findings use stable route/rule/header-or-status identities, set `test_node_id=None`, and keep any attempt key out of the fingerprint. Unobserved configured expectations produce UNKNOWN coverage. Unknown routes use `None`; raw paths are never stored. No raw header values, query strings, bodies, exception text, or node IDs enter HTTP facts.

- [ ] **Step 1:** Add `test_http_security_rule_is_registered` through the existing advisor registry, then add `test_http_security_missing_configured_response_header_finding`, `test_http_security_expected_status_suppresses_finding`, `test_http_security_unexpected_status_finding`, `test_http_security_multiple_missing_headers_have_distinct_fingerprints`, `test_http_security_unobserved_expectation_is_unknown`, `test_http_security_facts_do_not_accept_values_or_bodies`, and `test_http_security_finding_fingerprint_ignores_test_attempt` through the existing report model; assert exact rule, route, severity and omission behavior without importing the not-yet-created module.
- [ ] **Step 2:** Run the registry test; expect the assertion that `HTTP-SEC-001` is registered to fail. Run the behavior tests after their public report path exists and require assertion failures, never collection or import errors.
- [ ] **Step 3:** Implement the normalized fact and evaluator using existing `Finding`, `AdvisorRun`, severity and fingerprint conventions; use distinct rules `HTTP-SEC-001` (HIGH, missing header) and `HTTP-SEC-002` (HIGH, unexpected status); both rule definitions are added to the advisor registry and matrix. Keep observed 500 without configured mismatch as internal evidence only; do not add a diagnostic rule or report format.
