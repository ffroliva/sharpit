# sharpit 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sharpit 0.2.0 shows what a FastAPI app *does* while you use it: HTTP exchanges, exceptions, SQL trace, live activity with N+1 detection, log tail, Alembic migrations, connection pools, health, threads and asyncio tasks, a REST API advisor on shared advisor plumbing, and an in-process HTTP probe. Every feature ships engine code, API routes, a UI panel and (where BootUI has one) a read-only MCP tool.

**Architecture:** Capture state lives in a new framework-free package `sharpit.engine.capture` (plain ASGI dicts and stdlib types). The FastAPI adapter adds one pure-ASGI `CaptureMiddleware`, wraps some exception handlers, attaches a log handler and SQLAlchemy class-level listeners, all on the **active** branch of `install()` only and only for enabled panels. SQLAlchemy is reached through `sys.modules` in `engine/sqla.py`, never imported. Advisors share `engine/advisors/` (rules, report helpers, retention, dismissals). The probe is a hand-rolled ASGI call into the host app object.

**Tech Stack:** Python ≥ 3.12, Starlette (via FastAPI ≥ 0.115), `packaging`, stdlib (`contextvars`, `logging`, `ast`, `configparser`, `tomllib`, `asyncio`, `threading`); test extra adds `sqlalchemy[asyncio]` (pulls `greenlet`), `aiosqlite`, `alembic`; uv, ruff, pyright strict, pytest; UI: Svelte 5 + Vite + TypeScript, vitest, Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-10-31-sharpit-0.2.0-design.md` (rev 2, called "spec" below). The MVP spec (`docs/superpowers/specs/2026-10-30-sharpit-mvp-design.md`), `docs/how-it-works.md` and `docs/reference/BOOTUI-CONTRACT-MVP.md` still hold. BootUI source (read-only) at `C:\development\github\boot-ui`; path abbreviations `DTO/`, `ENG/`, `AC/`, `views/` as in spec §1.

**Plan revision 2** applies the executability review (2 blockers, majors M1–M12, 13 minors) and the coverage review (6 high, 14 medium, 12 low). Every finding is applied in the task it belongs to; the few rulings are listed at the end under "Review rulings".

## Global Constraints

- Runtime deps stay exactly `starlette` and `packaging` (`tests/test_packaging.py` enforces it). `sqlalchemy`, `aiosqlite`, `alembic` join the `test` extra only. sharpit never imports `sqlalchemy` (only reads `sys.modules`), never imports `alembic`, never uses `httpx` at runtime.
- `src/sharpit/engine/**` imports neither `fastapi` nor `starlette` (existing import-boundary test extended to `engine/capture`, `engine/advisors`, `engine/probe.py`, `engine/sqla.py`).
- **Inactive adds nothing.** No middleware, no log handler, no SQLAlchemy listener, no wrapped exception handler, no contextvar set. The same holds per panel: a disabled panel installs no hook (spec §6.1 table).
- `install()` creates no threads and no timers. Executors (health: 2 threads) and stream timers are created lazily on first use, on the running loop.
- Every captured value is masked at capture time: paths (`mask_path`), queries, headers (`mask_header`), SQL text and errors, log messages, exception messages, health details, probe headers and body (`mask_text`). Buffers never hold raw secrets. No `{@html}` on captured values in the UI.
- Every buffer is a fixed, configurable cap (spec §12 table). Every new route lives under the API path and passes the full guard chain; disabled panel → contract 403 on all methods; read-only panel → 403 on POST/DELETE.
- No GET and no MCP tool opens a socket, checks out a DB connection, runs a user callable, imports a module or writes a file. DB reads and health checks are guarded POSTs. MCP stays read-only; action tools are CLI-endpoint only.
- Capture hooks never break a host request: each catches its own errors and logs one warning per hook. **Each task that adds a hook adds its own "hook raises" test** (named in its Step 1).
- JSON: every key emitted (nulls kept), camelCase, BootUI record components unless spec §17 logs a deviation. Error bodies `{"error": "..."}` verbatim from the spec. **Each task with a new report adds `test_shape_keys_match_bootui`** comparing sorted keys (nulls present) to a frozen list with a `# ported:` cite to the DTO record.
- MCP tools: name and `inputSchema` verbatim from BootUI. Task 2 commits `tests/fixtures/bootui_tools_0_2_0.json` (the 12 BootUI schemas, with the source commit) and a parametrised test `test_mcp_schema_matches_bootui` in `tests/engine/test_tools.py`; each task adds its tool to the parametrisation (`get_alembic_migrations` is a logged name deviation). New schema properties (`id`, `state`, `scanId`, …) get entries in `tools._SCHEMA_NAMES`. Tool handlers run in a `ToolGate` worker thread, off the event loop.
- Each ported test cites its BootUI source: `# ported: ExceptionStoreTests.reopensResolvedGroup`. Derived cases without an oracle: `# derived: <reason>`.
- **Test basenames are unique across `tests/`** (no `__init__.py`; pytest's default `prepend` import mode fails on duplicates).
- **SQLAlchemy test modules:** a test module that needs `sqlalchemy`, `aiosqlite` or `alembic` imports them with `pytest.importorskip(...)` (or lazily inside a test) and sets `pytestmark = pytest.mark.needs_sqlalchemy`. A conftest collection hook (Task 5) fails collection of any module that imports `sqlalchemy` at top level without the marker. Tasks 5, 7, 8 and 13 follow this.
- **New GET path parameters** get a value in `_PATH_PARAMS` in `tests/conftest.py` in the same task (`id`, `name`, `ruleId`), or `get_paths()` fails collection.
- **New POST/DELETE routes** get a row in `WRITES` in `tests/test_safety_matrix.py` in the same task; `test_write_route_table_is_complete` (Task 4) enforces it.
- **Panel availability:** `available_reasons(ctx) -> dict[str, str | None]` in `src/sharpit/fastapi/adapter.py` (Task 1) is the one place a panel's `available` reason is computed. Each feature task replaces its own panel's entry and names it under "Produces".
- **Capture state:** `ctx.capture: CaptureState` (Task 2) is the one place stores live. Each task fills its own field and names it under "Produces".
- Commits: conventional prefix, plain message, **no AI attribution of any kind**. Never push, never touch `master` or other worktrees. Work only in `C:/development/github/sharpit-0.2.0-wt` on `feat/0.2.0`.
- Any command that may run longer than ~8 s runs in the background (`run_in_background`), read its output when notified.
- Plain, simple English in docs; GitHub links always `github.com`.

**Commands used in every task.**
- Targeted tests: `uv run --no-sync pytest -q <paths>` (foreground only for a single file; otherwise background).
- UI (from `ui/`): `npm test` (vitest), `npm run check`, `npm run build` (refreshes `src/sharpit/ui/static`; commit the output).
- **Full gate** (background): `uv run --no-sync ruff check && uv run --no-sync ruff format --check && uv run --no-sync pyright && uv run --no-sync pytest -q`. Every task ends green on the full gate before its commit.

## Review Focus

1. **A secret reaching any output through a capture side door** — SQL literal, `[parameters: ...]` in an `IntegrityError`, `echo=True` log lines, a path segment token, an `Authorization` header, a probe `Set-Cookie`, a health DSN, an Alembic ini error. Expectation: never, in API, MCP, CLI and the raw buffers. Pinned by the masking corpus rows each task adds (`tests/test_masking_corpus.py`) and the per-feature `METADATA_ONLY` tests.
2. **Inactive or partially disabled sharpit touching the host app.** Expectation: `app.user_middleware`, logger handlers, `app.exception_handlers` and SQLAlchemy events identical to a never-installed app. Pinned in Task 2 (`test_inactive_adds_nothing`, `test_all_capture_panels_disabled_adds_nothing`), Task 3 onward (`test_disabled_panel_installs_no_hook`) and Task 5 (SQLAlchemy events).
3. **A capture hook breaking or slowing a host request.** Expectation: a raising hook leaves the response unchanged with one warning; overhead ≤ 0.2 ms per request and ≤ 50 µs per statement. Pinned in Task 2 (`test_hook_failure_leaves_response`, `test_request_overhead_budget`), Tasks 3–5 (one hook-failure test per hook) and Task 5 (`test_statement_overhead_budget`).
4. **The probe reaching sharpit or a socket.** Expectation: 400 or 403 for every path trick, no socket ever. Pinned in Task 11 (`test_probe_cannot_reach_sharpit` parametrised, `test_probe_opens_no_socket`).
5. **Streams holding `--reload` or leaking slots.** Expectation: shutdown within lifetime + 1 s; a dropped client frees its slot; a non-reading client does not grow memory. Pinned in Task 3 and `tests/fastapi/test_change_streams.py` (Tasks 4–6).
6. **Timed-out work piling up threads.** Expectation: single-flight and probe slots held until the worker really returns. Pinned in Task 7 (`test_timed_out_check_holds_single_flight`, `test_timed_out_refresh_holds_single_flight`) and Task 11 (`test_timed_out_probe_holds_slot`).
7. **The no-side-effects sweeps proving something.** Expectation: the sweeps also run against an app with an engine, a health check, an Alembic ini and captured data. Pinned in Task 7 (`sweep_app_sqla` fixture).
