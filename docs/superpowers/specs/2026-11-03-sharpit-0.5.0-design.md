## 1. Intent

- **Every BootUI 2.2.0 panel id has a Python/FastAPI answer.** At 0.4.0, 7 of 31 are not started and 1 is parked
  (`PARITY.md`). 0.5.0 implements all eight, with golden parity where a golden exists and an honest "unverified" with

  none blocks the panel release.
- **Patch the 0.4.0 gaps the benchmark named** (U4, U5, U6) only where a gap is proven against the bench twin cases;
  most of them shipped in 0.4.0 (§8).

### 4.1 SQLAlchemy gatekeeper becomes a package

`engine/sqla.py` is 717 lines on `main`; T-unbounded-read adds 139, R-transactions' commit-failure event and
A-database-advisor's inspector reads would cross the 1000-line ratchet, and Architecture rule 4 allows SQLAlchemy in
one file. F5 moves it to `engine/sqla/` (`__init__.py` re-exports today's public names so no caller changes;
`listeners.py`, `readonly.py`, `events.py` (connection events), `inspect.py` (empty: database-advisor fills it),
`orm.py` (ORM load hooks)). `tests/engine/test_import_boundary.py` rule 4 reads "SQLAlchemy only under
`engine/sqla/`"; AGENTS.md rule 4 says the same; the planted-violation test still bites from `engine/collectors/`.
Precondition: T-unbounded-read is merged to `main` first (or F5 rebases onto it), so its 139 lines move once.
If the owner rejects the package (§13 O6), F5 drops 4.1 and the SQLAlchemy lanes serialise on one file with a
line-count check before each (R0 chain in PLAN.md).

### 4.2 App-source AST layer `engine/appsource.py`

Shared by B-security (static checks), C-architecture and C-fastapi (WAVE-B §7: "build §6's AST layer first").
stdlib `ast` + `tokenize` only; no import, no exec. Input: a package root resolved by the adapter from the app object's
module: the top-level package of the module whose globals hold the app instance (the same `sys.modules` read G6's
autodetect does; `type(app).__module__` would name FastAPI, not the app), else `install(app_package=...)`. Bounded: `max_files` (default 2,000), `max_file_bytes` (default
512 KiB), never follows a symlink outside the root, skips `site-packages`/`.venv`/`node_modules`. Output: an immutable
`SourceIndex` (module name → parsed tree, imports, function defs with `file:line`), built on POST only, cached per scan.
Every read happens inside the scan; a GET never opens a file (`test_get_after_scan_opens_no_source_file`).

### 4.3 Advisor scan core `engine/advisors/scan.py`

WAVE-B §1: GET cached report, POST scan single-flight (`engine/singleflight.py`), GET `rules/{id}/violations` paged
(`engine/paging.py`), `scan` status `NOT_SCANNED`/`RUNNING`/`COMPLETED`/`PARTIAL`/`FAILED`, `severityCounts` listing
every severity, dismissal through the existing `advisors/dismissals.py`. One generic core; each advisor lane supplies
its rule list and its `AdvisorSpec` row. Its `test_advisor_scan_core_*` tests use a two-rule fake advisor.

### 4.4 Settings, surface, gate

- Pre-create every 0.5.0 settings field in `settings.py` and its env row (lanes never edit `settings.py`):
  `mysql_max_*` (WAVE-A §6), `database_advisor_*` bounds, `architecture_max_files`, `architecture_max_file_bytes`,
  `security_*`/`fastapi_advisor_*` none (BootUI has none), `memory_*` and `workload_*` placeholders gated off.

- `lane_gate.py` refuses a lane whose plan header says `Council: required` when `council.md` is missing from its lane

## 5. Panels

Every panel lane meets 0.4.0 §6.1 items 1–10. Additions for 0.5.0:

- **Pre-scan vs post-scan parity.** The goldens for `security`, `architecture`, `fastapi`, `database-advisor` and
  `mysql` are the pre-scan shape (`NOT_SCANNED`/`NOT_READ`, empty lists). A lane asserts parity on that golden; it
  asserts the post-scan shape only against G0's `scanned.captured.json` if it exists when the lane reaches its parity
  task. Without it the PARITY row reads `unverified (post-scan)`.
- **No `getattr` on unknown classes.** Introspection reads `vars()` of known Starlette/FastAPI route classes only; a
  route of any other class is `unknown` + `bestEffort`. Every introspecting lane carries the trap-property test.
- **Source-reading advisors** use F5's `appsource` only; a violation message names rule and `file:line`, never the
  source text of the line (masking of a secret literal is then structural).

### 5.7 A-mysql

WAVE-A §6, mirroring A-postgresql's structure (`engine/collectors/postgresql/`). `bounded_read_only` already has the
MySQL/MariaDB branch (`engine/sqla.py:644`); the lane adds collectors only. Sections: sessions
(`performance_schema.threads`/`processlist`), statements (`events_statements_summary_by_digest`, digest text through
the normaliser and masker, ≤ 400 chars), indexes, tables, lock waits (`sys.innodb_lock_waits` or
`performance_schema.data_lock_waits`), replication channels, curated settings allow-list. Each optional section runs
inside `begin_nested()`. Leased MySQL 8.4 container for the integration tests; a run where they only skipped counts as
unverified (0.4.0 §6.1 item 9).

### 5.8 A-database-advisor

WAVE-A §4. POST scan through `run_db_read(read_only=True)`; SQLAlchemy `inspect()` reads live in
`engine/sqla/inspect.py`. 33 portable checks: schema (`DB-SCHEMA-*`: FK without index, table without PK, nullable FK,
...), ORM (`DB-HIB-*` → SQLAlchemy mapper analogues read from `install(models=...)` without configuring mappers),
runtime (`DB-RUNTIME-001` from the SQL Trace ring), driver and pool (`DB-DRIVER-*`, `DB-POOL-*` from the engine's
pool class and URL query, password never read), PostgreSQL and MySQL vendor rules (skip with a reason on other
dialects). Bounds: 300 tables, 300 columns, 100 indexes per table, 500 vendor rows, 20 s cooperative.

### 5.9 V-unverified (`data`, `sqlalchemy-statistics`)

`data`: the golden lists zero repositories, so items are unchecked (`UnverifiedParityWarning`). `sqlalchemy-statistics`:
no golden (`meta.json` `uncaptured`: no Hibernate statistics bean on tiny-ledger). Both can get goldens only by
changing the reference app (§13 O1). With them, the lane turns the item check on and fixes what it finds; without them,
PARITY keeps `unverified` with that exact reason. No code change is planned blind.

## 7. Benchmark items

### 7.1 U20-memory (gated: spike + owner)

Not a new panel: fills `activity`'s BootUI keys (`heapUsedBytes`, `heapMaxBytes`, `heapCommittedBytes`,
`heapAfterGcBytes`, journal `gc` events; all `null` today, `engine/capture/activity.py:255`) and adds test-session
facts. Python analogues, logged in §14 as "not 1:1 with JVM heap": RSS and the cgroup `memory.max` limit (sampled by
the existing activity sampler, never on a GET; §13 O3), gen-2 collections per minute from `gc.callbacks` (an integer
add in the callback; attached only while a test session runs or the panel's recording action is on), per-route
allocation via a `tracemalloc` snapshot diff and retained growth over N requests (test session only, marker
`@pytest.mark.sharpit(memory=True)` or `--sharpit-memory`), `memray` capture on demand (optional extra, gatekeeper
`engine/memray.py`, CLI-only action writing under `SHARPIT_STATE_DIR`; §13 O4). JVM GC tuning advice does not port;
no rule text is copied. Spike question: tracemalloc overhead on the bench corpus and whether snapshot diffs attribute
to routes reliably under xdist.

### 7.2 T-swallowed-2 (U1/U19, small)

0.4.0's rule already flags only when the handler neither re-raises nor logs, judged from the **handler's own body**
(`swallowed.py:3`), so a framework's WARN underneath (U19, Java D13) cannot hide an app swallow. And sharpit caches
the fact per handler and type, so a swallow inside a loop (U17's 16-catch limit) is still one finding. The lane pins
both with the bench twin cases (`test_library_warn_does_not_hide_app_swallow`, `test_swallow_in_loop_is_one_finding`)
and fixes only what those reds show. Two known edges to probe: a helper call that logs (`self._report(exc)`) counted
as a swallow (false positive) and a non-logger `.error(...)` call counted as logging (false negative). The fix for
either is an AST rule change behind its own red.

### 7.3 W-workload (U17, gated: spike + owner)

A jvm-pulse-style defined workload: `sharpit workload run --app module:attr --spec workload.toml` sends a defined set
of requests **in-process** (Starlette `TestClient`/`httpx.ASGITransport`, no socket), `--compare` runs it on two
revisions or settings and `--sweep` over a parameter; the output is one offline, shareable report (masked, no bodies,
aggregates only: per-route latency percentiles, query counts, findings). Flagging is **per request** with a
configurable minimum count (`--sharpit-min-requests`, default 1, the U17 answer), and "insufficient evidence" is
reported distinctly from "clean". Never reachable from a GET or MCP. Report format: §13 O5.

### 7.4 T-unbounded-read-2 (U3/U14, design first)

Builds on T-unbounded-read (paged routes: entities loaded vs page size), which must be on `main` first. Extension:
non-paged routes, evidence "entities loaded vs items returned", which needs the response item count. The spike
measures the cost of counting a top-level JSON array at the end of the body in the capture middleware against the
capture budget (never raised). Accept → lane; reject → logged in §14 as "paged routes only" and the bench forms D09–D11,
D16, D18 stay a documented gap.
