# CLI Task 7 review fixes

## Outcome

The CLI Task 7 round 1 fixes are pushed to PR #236 at `cbf80741`. The pull request remains open; no release or deployment
was performed. The lane suite passed 342 tests and the common suite passed 166 tests.

## Worked

- The 18 regression cases failed on assertions against the unmodified implementation before the implementation commit.
- The lane tests, common gates, strict type check, lint and format check passed on the pushed tree.
- Reading the BootUI 2.4.0 renderer and CLI tests directly kept table formatting, MCP acknowledgements, guard errors and
  exit codes aligned with the reference.

## Didn't work

| Failure | Root cause | Mechanism now in place |
|---|---|---|
| A missing output flush made the test raise `ValueError` while searching for an event. | The test assumed the event existed instead of asserting the contract. | The test asserts the flush event first, so a regression fails with a test assertion. |
| The first CLI import-boundary run rejected `contextlib`. | The CLI standard-library allow-list is deliberately explicit. | Broken-pipe redirection uses `os` only; `test_import_boundary.py` guards the allow-list. |
| The first common-gate run found two functions above the complexity limit. | Parser dispatch and MCP report validation had accumulated too many branches. | The dispatch and report checks are split into small helpers; `test_code_shape.py` pins the ratchet. |

## Rulings

- Piped JSON preserves the server body and UTF-8 bytes; terminal text may replace characters the console cannot encode.
- A direct MCP guard refusal keeps its reason and error exit without an extra request; catalog-confirmed tool refusals use
  the policy exit.
- `--fail-on` is exposed only for supported tool commands; misuse is a usage error with exit 2.

## Open

- PR #236 still needs CI and review. No live server verification was run because the change is confined to the CLI client.
